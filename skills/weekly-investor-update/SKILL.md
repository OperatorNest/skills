# Weekly investor update

## Inputs

Ask for the reporting period, last update, current operating notes, source for each metric, recipient list, preferred length, draft deadline and time zone, disclosure rules, decisions, and asks. Use supplied answers before asking again.

## Steps

1. Collect notes and numbers for the exact start and end dates. Use the previous update as context, not evidence that an old status is still current.
2. Check each number against its source, unit, and reporting period. When records conflict, show both and ask which applies. Leave missing numbers as visible questions; do not average conflicting totals or repeat last week's number as current.
3. Draft progress, setbacks, key numbers, decisions, and specific asks. Label plans as plans. Omit private customer details that the founder has not authorized for disclosure.
4. Present the subject, complete email, recipients, and source notes for review. Mark claims needing confirmation and keep the draft available for revision.
5. If numbers arrive late, resume from the saved draft. Before an approved send, confirm the final version and recipients still match the approval. If they changed, hold for a new decision.

## Approval boundary

The founder must approve the final wording and recipients before sending. Preparing an update does not authorize sending, paying, deleting, or publishing. Require the human's OK for each such action. Stop any claim with an unknown period, disputed metric, or unauthorized disclosure until resolved.

## Output

Return one held email draft: subject and reporting period, progress, setbacks, key numbers with source notes, decisions, asks, and visible questions. Show recipients and state whether anything was sent. Source notes may be removed from the email only after the founder confirms them.

Append a receipt: reporting period, sources checked, draft version, unresolved claims, recipients, approval decision, and send time if sent.

## Check against the brief

Trace every number and milestone to a current source, check disclosure rules and requested length, and verify that each ask names a concrete next step. A draft with unresolved claims is held, not ready to send. Use confirmed scheduling tools only when recurrence was requested; otherwise return this run's draft.
